◆ eth_json_error_message()

bool eth_json_error_message ( const char * resp,
char * out,
size_t out_size )

Extract the JSON-RPC error.message from a response body.

The counterpart to eth_json_result_string, and the only place a node ever says why it refused a transaction: "insufficient funds for gas * price + value", "nonce too low", "transaction underpriced". Dropping it on the floor is what turns every one of those into an identical "Broadcast failed" on the panel, which tells an operator nothing they can act on.

A message longer than out_size is truncated rather than rejected — half a reason beats none, and the caller's buffer is a panel line, not a log.

Parameters
[in]respNUL-terminated response body.
[out]outNUL-terminated message on success; untouched otherwise.
[in]out_sizeCapacity of out.
Returns
true if the body parsed and carried a non-empty error message.

◆ eth_json_receipt_check()

eth_json_receipt_t eth_json_receipt_check ( const char * resp,
const eth_receipt_expect_t * want )

Classify a receipt AND check it is the payment that was asked for.

A status of 0x1 alone proves nothing: a node that never broadcast our transaction can answer with the receipt of any other successful one. So on top of eth_json_receipt_status this requires transactionHash to be the hash computed on the device, to to be the expected contract (or payee), and — for a token — a Transfer log from that contract to payee for exactly amount. A mined receipt failing any of those is ETH_JSON_RECEIPT_MISMATCH, never SUCCESS or REVERTED.

◆ eth_json_receipt_status()

eth_json_receipt_t eth_json_receipt_status ( const char * resp)

Classify an eth_getTransactionReceipt response body.

Parses the JSON and inspects the top-level result: null means the tx is still pending; an object's status field ("0x1" = success, anything else = reverted) gives the final verdict. Any other shape (invalid JSON, result neither null nor object, missing/non-string status) yields ETH_JSON_RECEIPT_ERROR.

Extract the top-level "result" string from a JSON-RPC response.

Uses a real JSON parser (cJSON) instead of strstr so that JSON-RPC error objects, HTTP error bodies, or look-alike substrings are rejected.
